# Эврикус · помощь с KYC

Исходники, тесты, оформление и документация собраны в одном репозитории: [veetma0/everykyc_bot](https://github.com/veetma0/everykyc_bot). Рабочая папка — `Desktop/everykyc`.

**Railway:** готовые настройки в `railway.json`, Dockerfile и `.env.railway.example`. Порядок подключения и переноса существующих заявок: [docs/RAILWAY.md](docs/RAILWAY.md). На рабочем Mac есть личный `.env.railway` с заполненными переменными; он исключён из GitHub. Требуются Volume `/app/data` и одна копия бота.

**Локально:** `.venv/bin/python manage_service.py status`; перед переключением на Railway — `.venv/bin/python manage_service.py stop`. В GitHub Actions проверяются тесты и сохранение данных в контейнере; секреты для CI не нужны.

Бот: [@everykyc_bot](https://t.me/everykyc_bot). Помощь с KYC — проверкой личности своего аккаунта Claude. Все заявки, ответы и карточки находятся внутри Telegram-бота. Переходов в личку оператора нет.

## Услуги и цены

| Направление | Условия |
| --- | --- |
| Claude · Армения | $35 за сопровождение |
| Claude · Европа | $50 за сопровождение; конкретную страну уточняет оператор |

Доступен только Claude. Alipay и демонстрационные направления отключены. Старые кнопки не создают заявки и предлагают открыть Claude; прежние заявки и переписка остаются доступны.

Это цены сопровождения, заданные владельцем сервиса. Они не являются тарифами Claude. Проверка проводится владельцем аккаунта на собственные данные и с учётом действительной страны проживания. Результат определяет официальный сервис.

## Для клиента

Главное меню — три кнопки: **Claude**, **Моя карточка**, **Как это работает**. Путь: **Claude → регион и цена → создать заявку → дождаться оператора**. В заявке можно сразу описать вопрос без личных данных. География и цена открываются после выбора Claude; до заявки три нажатия. Стоимость и условия показаны до заявки. Повторно вводить имя, username и анкету не нужно — карточка использует профиль Telegram.

В основной карточке заявки — услуга, цена, статус и три кнопки: **Детали**, **Переписка**, **Меню**. Для ответа достаточно обычного сообщения в этот чат. Инструкция, демо-оплата, личная карточка и закрытие находятся в **Деталях**. Под сообщением оператора — только **Моя заявка**.

Ответ через Telegram Reply привязан к исходной заявке. Если она закрыта, сообщение не уйдёт в новую заявку по ошибке. Из инструкции можно вернуться к выбранной услуге; устаревшие кнопки дают понятный возврат к текущему экрану.

На одного человека открыта одна активная заявка. Выбор другого направления не подменяет её услугу и цену: бот объяснит, как продолжить через текущую заявку. Закрытие требует подтверждения; после него можно создать новое обращение.

- `/start` — главное меню.
- `/services` — услуги и условия.
- `/profile` — моя карточка.
- `/status` — текущая или последняя заявка.
- `/help` — порядок работы и инструкции.
- `/privacy` — сведения о данных.
- `/id` — свой Telegram ID.

## Для оператора

Основной путь: **Следующая заявка → написать ответ → Следующая**. Команда **/next** делает то же самое. Поле ответа открывается автоматически; над ним видны имя клиента, номер заявки и последние сообщения. Полная переписка доступна из карточки рядом. Повторный `/next` возвращает к уже взятой заявке; кнопка **Следующая** на карточке позволяет её пропустить.

После подтверждённой доставки ответа статус автоматически становится **Ждём клиента**. Клиент видит **Нужен ваш ответ**. Его сообщение возвращает обращение в очередь. Неопределённая или неуспешная доставка не убирает заявку из работы и не запускает автоматический повтор ответа.

Очередь идёт от наиболее давнего ожидающего обращения. Заявка закрепляется за оператором на 15 минут; второй оператор не получает её одновременно. После ответа, закрытия, пропуска или выхода через `/admin` закрепление освобождается. Ответ по старому уведомлению блокируется, если после него уже ответил другой оператор: нужно открыть свежую переписку. Свой ответ можно дополнить через обычный Telegram Reply на подтверждение отправки.

При 20 и более ожидающих ответов уведомления объединяются: не более одной попытки отправки сводки каждому оператору за 15 секунд. Все клиентские сообщения сохраняются, даже если сводка не доставлена. Сводка не является привязкой к конкретному клиенту. Подробнее: [быстрые ответы и очередь](docs/fast-replies.md).

По умолчанию с Telegram ID оператора `/start` открывает кабинет. Кнопка **Режим клиента** переключает на полноценный клиентский путь. **В админку** возвращает обратно. Команды `/client` и `/admin` делают то же самое.

Режим сохраняется после перезапуска; `/start` открывает меню выбранной роли. В режиме клиента можно создать собственную заявку, отправлять обычные сообщения и выбирать демо-сеть. Затем в админке открыть эту же заявку и ответить. Это реальная заявка вашего Telegram-профиля, которую можно закрыть после проверки. Служебное уведомление самому себе в режиме клиента не дублируется.

У обычных пользователей переключателя нет. Режим не выдаёт и не отменяет права администратора; старые кнопки и ответы из админки не выполняются в режиме клиента. Чтобы ответить на старое сообщение клиента, сначала вернитесь в админку.

- **Клиенты** — список пользователей и их карточки. Ваш профиль тоже появится здесь после собственной заявки; дополнительных вымышленных клиентов бот не создаёт.
- **Карточка клиента** — имя, Telegram ID, обращения, текущая заявка и приватная заметка.
- **Изменить заметку** — ответьте на специальное приглашение. Текст виден только оператору. Для очистки отправьте минус.
- **Ответить** в заявке — поле ответа открывается сразу с номером заявки и именем клиента. Также работает обычный Telegram Reply на уведомление, карточку или подтверждение отправки конкретной заявки.
- Текст без привязки к заявке никому не пересылается.
- `/preview` — дополнительный просмотр без изменений. Для полного прохождения используйте **Режим клиента**.
- `/style` — дополнительная проверка премиум-эмодзи Telegram.

Статусы клиента: **Ждёт оператора → В работе → Нужен ваш ответ → Помощь завершена / Закрыта**. В кабинете оператора «Нужен ваш ответ» отображается как **Ждём клиента**. Доставка ответа и автоматическая смена статуса сохраняются одной операцией. Новый клиентский ответ, поступивший во время отправки, остаётся в очереди.

Новое сообщение клиента отменяет актуальность старого подтверждения закрытия. Оператор сначала открывает обновлённую заявку. Просмотр последних сообщений убирает отметку о непрочитанном.

«Помощь завершена» относится к сопровождению, а не к автоматическому подтверждению KYC. Если Telegram не подтвердил доставку ответа, оператор увидит это. Текст останется в истории; неопределённая отправка автоматически не повторяется.

## USDT · демо

В заявке доступны **37 вариантов**: 13 сетей прямого USD₮, 23 направления USDT0 и отдельный пример BEP20. Категории не смешаны. На первом экране — TRON, TON и Ethereum; остальные открываются страницами. После выбора сети кнопка **К заявке** возвращает к обращению, а **Выбрать другую сеть** позволяет изменить демо-вариант.

**Адресов, QR-кодов, реальных счетов, комиссий и кнопки «Оплачено» нет.** Выбор сохраняет только демонстрационный вариант. Статус и цена заявки не меняются. В закрытой заявке доступен только просмотр.

Цена услуги указана в USD. Курс, сумма в USDT и платёжные условия не выдумываются. Для продажи цифровых услуг внутри ботов Telegram требует Stars; перед реальным приёмом оплаты нужно определить подходящую схему. [Правила Telegram](https://core.telegram.org/bots/payments-stars#can-i-accept-payment-in-cryptocurrency-instead-of-telegram-stars).

Списки сверены с [Tether](https://tether.to/en/supported-protocols/) и [USDT0](https://docs.usdt0.to/technical-documentation/deployments). Исторические сети не выдаются за действующие способы перевода.

## Оформление и аудитория

Новые название, описание и стартовый баннер 640×360 опубликованы через официальный BotFather Mini App. Наличие баннера проверено после повторного открытия настроек. Аватар подготовлен и загружен отдельно. Исходники и промпты — в `assets/`.

Все кнопки используют обычное нейтральное оформление Telegram — без синей, зелёной и красной заливки. Главные действия выделяются расположением и короткой подписью. Карточки показывают сначала активную заявку, затем историю и заметку оператора.

Гипотезы аудитории и источники — в [docs/audience-and-ux.md](docs/audience-and-ux.md). Основной фокус: люди, которым нужна понятная помощь с собственным аккаунтом без длинных анкет. Выбор, цена и следующий шаг видны заранее. Возраст, доход, доли рынка, отзывы и гарантии результата не выдуманы; гипотезы ещё предстоит проверить на клиентах.

## Поиск и источники заявок

Отображаемое имя: **Эврикус · KYC Claude**; username остаётся `@everykyc_bot`. При запуске бот синхронизирует имя и оба описания для русского языка и версии по умолчанию.

Команда **/sources** в режиме администратора показывает людей, запустивших бот по размеченным ссылкам, людей с последующей заявкой и число обращений. Учитывается первая распознанная метка, повторные запуски одного человека не увеличивают число людей. Старые заявки не получают источник задним числом; операторы исключены. Это не поисковые показы, позиции, все клики или оплаты.

Актуальная проверка фактов о поиске и KYC: [docs/claude-only-review.md](docs/claude-only-review.md). Предыдущие маркетинговые черновики и отчёты помечены как архив: они описывают прежний каталог. Позиции не объявляются измеренными или улучшенными только на основании изменения имени. Старая метка источника Alipay сохранена для непрерывности исторической статистики; она не открывает отключённую услугу.

## Запуск и обслуживание

Бот подключён как фоновый сервис macOS. Команды из папки проекта:

```sh
.venv/bin/python manage_service.py status
.venv/bin/python manage_service.py restart
.venv/bin/python manage_service.py stop
.venv/bin/python manage_service.py install
```

Нужны включённый Mac, интернет и сеанс пользователя. Во время сна компьютера бот недоступен. Для работы при выключенном Mac перенесите проект на сервер.

Ручной запуск — `Запустить.command`. Второй экземпляр поверх фонового сервиса не запустится. Токен хранится только в локальном `.env` с ограниченным доступом и не включается в архив.

На новом компьютере нужен Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполните `BOT_TOKEN` и `ADMIN_IDS`. Для нескольких операторов укажите числовые ID через запятую. Каждый оператор должен открыть бота и нажать Start. Доступ не выдаётся по username или первой регистрации.

```sh
.venv/bin/python -m verifydesk --check
.venv/bin/python -m verifydesk
```

На сервере можно использовать Docker:

```sh
docker compose up -d --build
docker compose logs --tail 30
```

Перед переносом остановите прежний процесс: один токен обслуживает один polling-процесс. Сторонний webhook автоматически не удаляется.

## Данные и проверка

База — `data/desk.sqlite3`. В ней Telegram ID, публичное имя, username, даты обращений, услуги, цены, тексты, статусы, заметки оператора и демо-сеть. Вложения не скачиваются и не пересылаются. В инструкции запрещено присылать ссылку проверки, документы, селфи, пароли и коды входа. Автоматического определения чувствительных данных в обычном тексте нет: отправленный текст сохраняется как сообщение. Срок ссылки определяется приглашением; «одно нажатие» и 30–50 минут не выдаются за универсальные ограничения.

Сообщения сохраняются до удаления владельцем сервиса. Удаление локальной записи не удаляет копии из Telegram. Тексты переписки и токен не выводятся в журналы. Длинные сообщения принимаются до 2400 единиц текста; эмодзи могут занимать больше одного символа. В истории текст открывается целиком отдельной кнопкой. Редактирование сообщения в Telegram не меняет сохранённую запись заявки.

Копия базы с учётом WAL:

```sh
.venv/bin/python -c "import sqlite3; s=sqlite3.connect('data/desk.sqlite3'); d=sqlite3.connect('data/backup.sqlite3'); s.backup(d); d.close(); s.close()"
```

В Docker данные хранятся в томе `bot_data`; не удаляйте его при обновлении. Перед миграцией остановите старый процесс: прежний код не должен работать с новой схемой.

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
```

Тесты используют имитацию Telegram API и не рассылают сообщения клиентам. Итоги — в `Проверка.md`. Архив исключает `.env`, рабочую базу, журналы и окружения Python.
